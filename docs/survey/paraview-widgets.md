# ParaView's Qt widgets: what GridForge can copy

Survey date: 2026-11-16. Purpose: decide which of ParaView's BSD-3-Clause Qt
widget classes GridForge can copy into its own tree ("level 2": copy the
files, keep their headers, list them in NOTICE) without linking ParaView or
pulling in its server manager.

## What was read

- ParaView, commit `afcca0d9f1a22c9e448e40293d62c7e42ba04399` (2026-11-16),
  sparse checkout of `Qt/Widgets`, `Qt/Core`, `Qt/Components`,
  `Copyright.txt`. Its `ThirdParty/QtTesting/vtkqttesting` submodule points at
  qttesting commit `4e0a3eb39d206d5fb49b25e89999b204afc27041`, cloned
  separately (https://gitlab.kitware.com/paraview/qttesting.git) to identify
  its headers.
- VTK, commit `6b16e362c6c2b9dceee1dc1d460d131fa564debf`, file list only, to
  tell VTK headers from ParaView headers. The VTK 9.5 installed here
  (`/usr/include/vtk-9.5`, `/usr/lib/x86_64-linux-gnu/cmake/vtk-9.5`) has
  `vtkNumberToString.h`, `vtksys/RegularExpression.hxx` and an imported
  `VTK::vtksys` target.
- Method: every `#include` line of every `.h` and `.cxx` in the three
  directories, followed transitively **at class level**: if a file includes
  `pqX.h`, then `pqX.cxx` must be copied too, so its includes count. An
  include was classed as Qt, C++ standard library, VTK (present in the VTK
  tree and not in ParaView's), qttesting (present in the qttesting tree), or
  ParaView (anything else in ParaView's tree outside `Qt/`). The scripts are
  in the session scratchpad, not in the repository.
- No code was built or run.

## Module facts

`Qt/Widgets/vtk.module` declares `ParaView::pqWidgets` with `DEPENDS
ParaView::qttesting ParaView::Versioning VTK::GUISupportQt` and `PRIVATE_DEPENDS
VTK::IOCore ParaView::RemotingServerManager ParaView::VTKExtensionsCore`. The
sources tell a smaller story:

- **Server manager**: only `pqTreeWidget.cxx` includes ParaView headers
  (`vtkPVXMLElement.h`, `vtkSMProperty.h`, `vtkSMPropertyGroup.h`), for three
  `setMaximumRowCountBeforeScrolling()` overloads (`pqTreeWidget.h` lines
  45 to 47).
- **Versioning, VTKExtensionsCore, IOCore**: no file in `Qt/Widgets` includes a
  header from them (grep for `vtkPV`, `PARAVIEW_`, `Version` and `#include
  "vtk` finds only the three lines above, `vtkNumberToString.h` and
  `vtksys/RegularExpression.hxx`).
- **VTK actually used**: `vtkNumberToString.h` (VTK::CommonCore, which
  GridForge already links) in `pqDoubleLineEdit.cxx`; `vtksys/RegularExpression.hxx`
  (VTK::vtksys, installed with VTK, not yet in GridForge's
  `find_package(VTK COMPONENTS ...)`) in `pqWidgetUtilities.cxx`.
- **Export macro**: every header includes `pqWidgetsModule.h`, generated by
  VTK's module system, for `PQWIDGETS_EXPORT`. Copied files need a three-line
  replacement header of our own (empty macro for a static library). This is
  the one edit every file needs and is not repeated below.

### Which files qttesting touches

qttesting (Kitware, BSD-3-Clause, `Copyright (c) 2000 Kitware Inc.` in its
`Copyright.txt`) records and replays GUI events for ParaView's XML tests.
In `Qt/Widgets` it is included by exactly these files:

| File | qttesting header |
|---|---|
| `pqColorButtonEventPlayer.h/.cxx` | `pqWidgetEventPlayer.h`, `pqTestUtility.h` |
| `pqColorButtonEventTranslator.h/.cxx` | `pqWidgetEventTranslator.h`, `pqTestUtility.h` |
| `pqColorDialogEventPlayer.h` | `pqWidgetEventPlayer.h` |
| `pqColorDialogEventTranslator.h` | `pqWidgetEventTranslator.h` |
| `pqConsoleWidgetEventPlayer.h` | `pqWidgetEventPlayer.h` |
| `pqConsoleWidgetEventTranslator.h` | `pqWidgetEventTranslator.h` |
| `pqLineEditEventPlayer.h` | `pqAbstractStringEventPlayer.h` |
| `pqTreeWidget.cxx` | `pqTimer.h` (a `QTimer` subclass in qttesting) |

The seven event classes exist only for test recording; GridForge's
walkthrough tests drive widgets directly and need none of them. The widgets
they serve do not include them.

### Resources

`Qt/Widgets/Resources/QtWidgets.qrc` (prefix `/QtWidgets`) holds
`pqCollapse`, `pqDelete`, `pqExpand`, `pqMinus`, `pqPlus`, `pqShowMenu` (SVG)
and `pqMultiply` (PNG). Used by `pqExpanderButton` (also its `.ui`),
`pqProgressWidget`, `pqScaleByButton`, `pqTreeViewSelectionHelper`. Two
classes also reach into `Qt/Components/Resources/pqComponents.qrc` (prefix
`/pqWidgets`): `pqTreeViewSelectionHelper.cxx` (`pqChecked`, `pqUnchecked`,
`pqSortAscend`, `pqSortDescend`, `pqClearSort`) and
`Resources/UI/pqSeriesGeneratorDialog.ui` (`pqReset`). Copy those SVGs with
the classes; they fall under the same Copyright.txt.

## Recommended for GridForge

For the Properties dock:

1. Collapsible sections: **pqExpanderButton** (the Properties, Display and
   View section headers in `pqPropertiesPanel.ui`) and **pqCollapsedGroup**.
   (Property groups inside a section collapse with a plain `QToolButton` in
   `pqProxyWidget.cxx` line 328.)
2. Search box: **pqSearchBox** with the one `QSettings` edit, plus its `.ui`
   and `pqAdvanced.svg`.
3. Numbers: **pqDoubleLineEdit** (short display, full precision when edited),
   **pqDoubleRangeWidget** and **pqDoubleSliderWidget**, **pqDoubleSpinBox**,
   **pqSpinBox**, **pqScaledSpinBox**, **pqLineEdit**, **pqVectorWidget** for
   3-component loads and directions.
4. Apply button: **pqHighlightablePushButton** for the highlight. ParaView's
   own Apply is a plain `QPushButton` named `Accept` (`pqPropertiesPanel.ui`
   line 25) with the search box right under it (line 85).
5. Colour: **pqColorChooserButton**.
6. Tables (steps table, amplitudes): **pqTableView**,
   **pqExpandableTableView**, **pqHeaderView**, **pqMultiColumnHeaderView**,
   **pqSeriesGeneratorDialog** (generate time points).
7. Study tree helpers: **pqTreeView**, **pqTreeViewExpandState**,
   **pqTreeViewSelectionHelper**, **pqItemViewSearchWidget** with
   **pqHighlightItemDelegate**.
8. Plumbing: **pqWidgetUtilities**, **pqScopedOverrideCursor**,
   **pqProgressWidget** (job progress with abort in the status bar).

For the quick-look view: **pqHierarchicalGridLayout** and
**pqHierarchicalGridWidget** (split views), **pqQVTKWidgetBase**, a
GridForge VCR controller written fresh over the eight pqVcr icons, and
**pqDataAssemblyTreeModel** if result blocks arrive as a `vtkDataAssembly`.

Build consequence: add `vtksys` to GridForge's `find_package(VTK COMPONENTS
...)` and link `VTK::vtksys` (or replace the three `vtksys::RegularExpression`
uses in `pqWidgetUtilities.cxx` with `QRegularExpression`). Copied widget
code belongs in `gf_gui`, never `gf_core`.
